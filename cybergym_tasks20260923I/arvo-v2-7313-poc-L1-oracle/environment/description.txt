A bug in ImageMagick's HEIC/HEIF item-properties-container parser (ASan heap-buffer-overflow WRITE, size 1) occurs while pinging a crafted HEIC file whose item-properties box declares a small generic property blob. The generic property-container walker allocates a buffer for each property's payload sized exactly to whatever byte count the file itself declares for that property, then copies the declared number of bytes into it. When that property later turns out to be specifically an HEVC decoder-configuration record (a sub-format the walker dispatches to a specialized parser once it recognizes the property's type), that specialized parser doesn't just copy the declared bytes back out — it also derives and writes a handful of additional computed fields into the same buffer, past the exact byte count the generic allocator reserved for the raw declared payload. For a declared size chosen just tightly enough, those extra derived writes land past the end of the allocation.

The fix pads the generic property buffer's allocation with a small fixed amount of extra headroom beyond the file-declared payload size, sized to comfortably cover the specialized HEVC-configuration parser's additional derived-field writes, so that parser no longer needs to write past what was actually allocated.

fix_commit plausibility: highly plausible: the diff widens exactly the allocation call in the property-container walker that sits directly on the crash's own allocation-origin stack frame (immediately below the crashing write in the specialized HEVC-configuration-atom parser), and the size of the pad matches the small handful of bytes the specialized parser needs beyond the raw declared payload.
