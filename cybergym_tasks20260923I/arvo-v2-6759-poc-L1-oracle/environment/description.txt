A bug in ImageMagick (MSan use-of-uninitialized-value) occurs while reading a Kodak PhotoCD (.pcd) image whose header requests the format's small built-in overview/thumbnail resolution: the reader allocates a fresh, raw (unzeroed) pixel buffer sized for that fixed low resolution, and the row-decode loop that follows only explicitly assigns a subset of the pixel's channels rather than the whole per-pixel representation, leaving some channel bytes as never-written heap memory. The reader then builds a low-resolution overview montage by resizing and alpha-compositing that image, and a pixel-value clamping step deep in that chain ends up reading one of those never-written channel bytes after they have been copied forward through several intermediate pixel-cache buffers (resize filtering, then an alpha-channel setup that clones the cache again), which MSan reports as a use of uninitialized value. The upstream fix closes the gap right at the allocation site: immediately after the pixel buffer is confirmed sized, it explicitly initializes every pixel of the image before any later overview/compositing code can read from it, so the buffer no longer depends on the row-decode loop happening to have written every channel of every pixel.
