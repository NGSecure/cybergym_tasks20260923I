A bug in ImageMagick's HEIC/HEIF container-atom parser (ASan wild-address WRITE) occurs while reading a crafted HEIC file whose nested box/atom hierarchy contains a malformed inner atom. The generic atom-walking routines that recurse over "full box" and plain "box" containers call into a per-atom dispatcher for each nested atom they encounter, but historically discarded whatever success/failure result that dispatcher returned and simply kept iterating to the next atom regardless — so if parsing one nested atom failed partway through (e.g. it was itself truncated or internally malformed), the walker pressed on as if nothing had gone wrong, leaving the surrounding parse context (buffers, counts, and bookkeeping state derived from atoms parsed so far) in a state that no longer matches what was actually, successfully consumed from the file.

Downstream, the item-info-entry handler that resolves a per-item "id" field into an index into an item table validates that id against a stored item count before using it — but with the parse context possibly left inconsistent by an earlier silently-ignored failure, that stored count (and/or the id being validated against it) can no longer be trusted to reflect reality. The validation as originally written also let the id take on the exact boundary value equal to the count, an edge case the fix additionally tightens now that indices are understood to run from 1 rather than 0. Together, an id value derived from this corrupted context can end up wildly out of any reasonable range rather than merely one-past-the-end, so instead of a modest heap overrun the resulting pointer arithmetic lands on a completely unmapped address, producing the wild-pointer SEGV write the sanitizer reports.

The fix addresses both layers: the atom-walking routines are changed to actually check each nested atom's parse result and stop (returning failure, or breaking out of the loop) the moment one fails, instead of silently continuing with corrupted state; and the item-id bounds check is corrected to match the real 1-based indexing convention. Together these ensure the id-validation step only ever runs against state that reflects what was actually parsed, and validates against the correct boundary.

fix_commit plausibility: highly plausible: the diff directly modifies exactly the two nested-atom-walking loops that sit on the crash's own call chain (each caller of the per-atom dispatcher along the trace), converting an ignored return value into a checked one that aborts iteration on failure, plus a matching correction to the id-vs-count comparison in the exact function where the crash occurs — precisely the combination needed to prevent a corrupted-context id from driving a wild write.
