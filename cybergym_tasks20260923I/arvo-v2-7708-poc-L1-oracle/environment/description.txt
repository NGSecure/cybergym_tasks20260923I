ImageMagick's MVG dashed-stroke renderer walks a small heap-allocated array of alternating dash/gap lengths that were parsed from a stroke-dasharray primitive; the array ends with a zero-valued sentinel entry that tells the walker to wrap back to the first length, and because of how the parser sizes the allocation there is also at least one further, uninitialized filler slot sitting past that sentinel inside the same buffer. Before the dashes are actually drawn, a preliminary pass advances the same walking index to account for a starting stroke-dashoffset by repeatedly subtracting whole dash lengths from the offset; everywhere else in this code, advancing the index is always immediately followed by re-checking it against the sentinel and rewinding it to the start when it lands there, but this preliminary offset-consuming pass has one path — taken when the remaining offset exactly matches the length of the segment just consumed — that advances the index without ever performing that check. When the offset happens to line up exactly this way, the walker is left pointing straight at the sentinel entry without that position ever being recognized as the end of the pattern. Ordinary per-vertex dash drawing then resumes from this stale, unchecked position: it treats the sentinel slot as if it were a normal value, advances once more into the adjoining uninitialized filler slot the allocator left past the sentinel, and — because that filler slot's leftover heap content is not reliably near zero — can advance a further step that runs completely past the end of the allocation, producing the 8-byte out-of-bounds heap read the sanitizer reports.
