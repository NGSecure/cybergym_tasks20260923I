In ImageMagick (ASan), parsing an MVG vector-graphics document whose path carries a degenerate stroke-dasharray (a dash segment immediately followed by a zero-length gap) causes the routine that expands a stroked path into its dashed sub-segments to hit an under-sized scratch buffer: the buffer's element count is derived from the input path's vertex count under the assumption that each input vertex contributes at most a bounded number of dash-boundary records, but the zero-length gap lets the inner dash-toggling loop keep firing without the input position advancing, so it emits more boundary vertices for that one input edge than the formula budgeted for, and a later vertex-record write lands past the end of the heap allocation (heap-buffer-overflow, write, one vertex-record wide, right at the boundary of the block). The fix simply enlarges the same allocation formula's constant so it reserves extra headroom per input vertex, without changing the dash-splitting loop's logic itself.
