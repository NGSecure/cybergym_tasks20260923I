In ImageMagick (MSan use-of-uninitialized-value), reading a LABEL-format image whose canvas ends up with zero width or height still runs the image's embedded "%[...]" property text through the FX calculator-expression evaluator; the recursive expression parser allocates a stack buffer for the current subexpression token but, in this degenerate zero-size case, does not write every byte of it before a later variable-name lookup step reads from that buffer, exposing uninitialized stack memory. The upstream fix does not touch the expression parser itself — it adds a guard right at the call site, in the property-interpretation code that feeds per-channel pixel expressions into the FX evaluator, that skips FX evaluation entirely whenever the image has zero columns or zero rows, so the buggy zero-size path inside the parser is simply never reached.
