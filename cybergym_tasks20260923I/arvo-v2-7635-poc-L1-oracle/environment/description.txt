ImageMagick's DNG/raw-image reader delegates raw-header parsing to its bundled LibRaw library (ASan build): a stack out-of-bounds read occurs while extracting a camera-model string from a raw file's fixed-size header block. Root cause: the parser reads a fixed 64-byte chunk from the very start of the input file into a small stack buffer without any guarantee that a zero byte appears anywhere within it; when those raw bytes match a Fujifilm-style camera header signature, a substring located near the tail of that same buffer is then treated as an ordinary NUL-terminated ASCII string and copied into a separate destination buffer using a C string-copy routine that scans forward until it encounters a zero byte, rather than being bounded to the number of bytes actually available. Because every byte of the header comes verbatim from attacker-controlled file content, a crafted file whose trailing header bytes contain no zero anywhere forces the copy to walk straight past the end of the small stack buffer holding the header in search of a terminator that was never there, reading adjacent stack memory before the sanitizer aborts. The defect is the missing length bound on that copy combined with implicit trust that a fixed-size, fully attacker-controlled byte block will happen to contain a NUL terminator.
