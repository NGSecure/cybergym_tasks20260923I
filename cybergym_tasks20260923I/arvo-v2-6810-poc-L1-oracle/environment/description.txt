In ImageMagick (MSan use-of-uninitialized-value), decoding a PS1 TIM raster whose header both declares an embedded color-lookup table and encodes its pixel data in a direct (non-indexed) per-pixel color format causes the reader to treat the image as palette-based purely because a lookup table is present, independent of which pixel-format branch actually decodes the raster data. The format-specific unpacking branch that runs for this pixel format never writes anything into the image's index channel at all -- it only ever assigns the color channels directly from the raw per-pixel sample bits -- so when the finished image is later synchronized as though it were palette-based, that synchronization step reads the index channel of a heap allocation that this decode path was never going to populate in the first place, exposing raw allocator memory instead of any value the decoder wrote. The fix reworks the allocation and initialization sequence for the pixel storage: it moves the final image dimensions to be known and the buffer to be extent-set before any decoding begins, adds a bounds check against how much raster data the file actually declares, and explicitly resets the newly sized pixel storage to a defined state right after allocation, so the never-written index channel reads back as that default instead of uninitialized heap content regardless of which per-pixel-format branch is taken.
