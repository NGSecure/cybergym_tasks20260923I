This crash occurs while ImageMagick's MVG (Magick Vector Graphics) interpreter processes a stroke dash-array property and then renders a dashed stroke along a drawn path. When the dash-array value list is parsed, the vector-graphics rendering code allocates a heap buffer for the numeric dash-length pattern sized to hold exactly the parsed values plus a small terminator slot, but the freshly acquired memory is not zero-initialized before use. Only the entries actually parsed from the input -- and, for an odd-length list, their spec-mandated duplicated copy -- get written, along with a single near-zero sentinel value meant to mark where the pattern should wrap back to its start. The code that lays dash segments along the stroked path then walks this array cyclically: it advances an index one entry at a time and treats any value close to zero as the wrap point, resetting the index back to the beginning of the pattern. Because the unwritten tail of that allocation was never guaranteed to contain such a sentinel (it is left holding whatever uninitialized heap bytes happened to be there), a crafted dash-array whose parsed length interacts with the buffer's exact sizing can leave the walk with no near-zero value to find within bounds: the index keeps advancing past the last legitimately written slot and off the end of the allocation entirely, producing an out-of-bounds heap read one 8-byte value past the buffer holding the dash pattern.
