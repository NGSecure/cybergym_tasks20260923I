Parsing a crafted MVG (Magick Vector Graphics) document containing a path/polygon drawing primitive triggers a small, out-of-bounds heap write while the primitive is rendered. Before rendering, the primitive list is converted into an internal vector-path representation: the code first scans the primitive list once to count how many primitive entries it holds, then allocates a heap buffer sized as a fixed linear function of that count, intended to be large enough for every path entry the fill loop can produce (ordinary points, duplicate-point elimination, and the extra "open subpath" / "closing ghost segment" entries inserted when a subpath's start and end points differ) plus one trailing terminator entry. For certain crafted sequences of primitive points that maximize how often the loop has to insert those extra closing entries relative to the point count, the loop consumes every slot in the buffer, so writing the final terminator entry lands one struct-sized slot past the end of the allocation. This is an off-by-one in the buffer's capacity formula, not in the fill loop's traversal bounds: the size estimate is a single element too small for the true worst case, so the last write silently overruns adjacent heap memory. The corrupted access is a narrow (4-byte) write, consistent with the small tag/discriminator field written first when the terminator entry is stored, rather than the larger coordinate data that follows it.
