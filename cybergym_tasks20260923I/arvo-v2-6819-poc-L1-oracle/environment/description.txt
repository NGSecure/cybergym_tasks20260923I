A bug in ImageMagick (MSan use-of-uninitialized-value) occurs while decoding a Palm Database (PDB) bitmap image: the reader allocates a pixel-index working buffer sized for the whole decoded raster but never clears it before filling it in from the encoded bitmap payload, and for at least one supported bit-depth/version combination the fill step does not end up writing every byte of that buffer, leaving a tail of leftover heap bytes untouched; those bytes are then copied unchanged into the image's per-pixel index channel as if they were valid color-table indices. The bad data only surfaces later, when the whole image is resynchronized against its colormap and each stored index is range-checked before being used to select a color — that check reads one of the never-initialized bytes, so MemorySanitizer's report points at the range-check call site, one frame removed from where the uninitialized byte actually originated (the unzeroed allocation in the PDB reader).
