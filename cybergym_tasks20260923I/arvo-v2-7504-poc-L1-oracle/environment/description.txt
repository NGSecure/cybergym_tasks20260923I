A bug in ImageMagick's JNG (JPEG Network Graphics) reader (MSan use-of-uninitialized-value, surfacing inside a generic blob-write helper's underlying fwrite call) occurs while pinging a crafted JNG file whose embedded chunk data is truncated partway through. The reader allocates a scratch buffer sized to the chunk's declared length and fills it byte-by-byte from the input stream in a loop, but that loop stops early — without an error — the moment the input runs out, leaving whatever portion of the buffer past that point untouched, still raw heap memory from the allocation. Nothing afterward accounts for the possibility that fewer bytes were actually read than the buffer was sized for; the whole buffer, uninitialized tail included, is treated as fully valid chunk data and later gets written back out (as part of how this particular chunk type is handled), and that write touches the never-filled tail bytes.

The fix adds an explicit pass immediately after the byte-by-byte read loop that zero-fills whatever portion of the buffer the loop didn't reach, so a truncated chunk still leaves the buffer fully defined even though the real declared length wasn't actually available in the file.
