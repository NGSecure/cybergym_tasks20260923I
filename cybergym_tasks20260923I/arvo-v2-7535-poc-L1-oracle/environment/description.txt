A bug in ImageMagick's MVG dashed-stroke renderer (ASan heap-buffer-overflow WRITE, size 40) occurs while rendering a crafted MVG path with a dash pattern applied. Before walking the path and synthesizing the extra boundary vertices a dashed stroke needs (splitting each drawn segment into dash/gap sub-segments), the renderer pre-sizes a scratch output buffer from a formula based purely on the original path's vertex count, with a small fixed constant added as safety margin for the handful of extra bookkeeping vertices the dash-splitting logic is expected to need beyond the raw count. For certain vertex-count and dash-array combinations, the actual number of boundary vertices the splitting logic produces exceeds what that fixed margin accounts for, and the final bulk copy of the synthesized vertices into the destination buffer writes past the end of the allocation.

The fix widens the safety-margin constant added on top of the vertex-count-based term, giving the dash-splitting logic more headroom before its output can once again exceed the buffer's capacity.
