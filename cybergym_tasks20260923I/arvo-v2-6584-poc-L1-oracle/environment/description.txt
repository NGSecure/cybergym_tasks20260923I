ImageMagick (MVG vector-graphics reader, libFuzzer/ASan build): rendering a crafted MVG `path`/bezier drawing primitive samples the curve into a fixed-capacity array of drawing-primitive records that the image-drawing routine allocates once up front, sized from a small fixed constant; for this input the curve-tracing step writes more sample points than that initial capacity holds before any of the routine's own per-primitive resize checks have a chance to grow the array, so the very first (never-yet-resized) allocation takes an 8-byte write just past its end — a heap-buffer-overflow write, not a read, and not an undersized-count-bypasses-a-check bug (the overflow comes from the curve producing too many points, not from a degenerate/zero value skipping a bounds check). The one-line fix simply raises that initial fixed constant to a much larger value, giving the array enough headroom for this class of path/bezier primitive so the same crafted input no longer outruns the buffer before a resize would occur; applying just this change on top of the vulnerable build reproducibly turns the crash into a clean exit on the same PoC.
